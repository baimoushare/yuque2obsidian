## 四、未提交版本的详细内容

### 1. 工程目录清理

本轮最大的变化不是新增业务功能，而是把项目目录从“开发中混有大量本地产物”整理为“更适合封版和归档”的状态。

具体表现为：

- 清理掉过去保存在仓库内的手工验证导出目录和快照结果
- 清理掉整个 Python 虚拟环境，避免依赖包继续占据版本库
- 清理掉根目录运行日志和重复素材，减少根目录噪音
- 保留 `output/`、`release/`、`cookies.json`、`desktop.settings.json` 这类实际运行和封版仍可能用到的目录与配置

这部分改动的价值在于：

- 让版本库更接近“源码 + 必要文档”的状态
- 降低后续封版、备份和交接时的混乱度
- 避免误把本地验证数据继续带进正式版本历史

### 2. 忽略规则补强

本次对 `.gitignore` 做了补充，新增忽略内容包括：

- `/.manual-packaging`
- `/.tmp-*/`
- `/.venv`
- `*.pyc`
- `desktop-launch.log`

这部分改动的意义很直接：

- 后续再次做本地手工验证时，`.tmp-*` 不会反复进入 Git
- Python 虚拟环境与字节码缓存不会再污染仓库
- 运行日志不会再重复出现在待提交列表中

它本质上是在给这次“目录整理”补一套长期有效的防回流规则。

### 4. Windows 打包脚本稳定性增强

虽然这轮主线是整理目录，但 [`build_windows_exe.ps1`](D:\01. 个人创作\编程工具\01. PC软件\09.语雀笔记导出MD\build_windows_exe.ps1:1) 里还有一组有实际价值的代码增强，不能简单视为格式变更。

本次打包脚本增强主要包括：

- 新增 `Test-PyInstallerArchive`，用于校验生成的 EXE 是否能被 PyInstaller 正常识别

- 发布前后都做 EXE 可读性校验，减少生成损坏包的风险
- 用 `$buildSucceeded` 和 `$finalExeValidated` 控制最终清理逻辑
- 当打包失败或校验失败时，保留临时目录用于排查，而不是无条件删掉现场

这说明当前未提交版本虽然没有继续扩导出功能，但对“可发布性”和“可诊断性”做了增强，属于很典型的封版前质量补强。
