可以把这部分理解为：桌面端已经从“导出启动器”，逐步变成“可持续操作的导出工作台”。

### 2. 失败重导与任务恢复链路

主要改动文件：

- `desktop_retry.py`
- `desktop_app.py`
- `src/failure-log.js`

这条主线是当前未提交内容里很实用的一部分：

- 新增 `desktop_retry.py`，用于从失败日志 CSV 中提取文档 URL、匹配知识库、生成重导计划。
- 桌面端新增 `startRetryExportFromFailureCsv`，支持直接读取失败日志，自动构造新的导出任务。
- 重导时会自动关闭增量导出，并使用失败日志所在目录作为输出目录，减少人工配置成本。
- 会返回未匹配到知识库的失败文档，避免“部分失败文档被静默忽略”。
- `src/failure-log.js` 不再只生成固定命名的失败 CSV，而是改为时间戳 + 毫秒 + PID + 随机串，降低覆盖风险。
- 失败日志本地化能力明显增强，对网络失败、HTML 误返回、图片下载异常、复杂块降级、资源丢失、加密块重加密失败等情况给出更明确中文说明。

这意味着当前版本已经不只是“记录失败”，而是开始具备“拿失败日志继续补导”的闭环能力。

### 3. Obsidian 落地能力继续深化

主要改动文件：

- `src/obsidian.js`
- `desktop/ui/app.js`
- `desktop_app.py`
- `src/exporter.js`
- `src/export-state.js`

目前未提交改动里，Obsidian 方向已经明显从“兼容导入”升级到“主动落地”：

- 新增 `src/obsidian.js`，专门处理 Obsidian 仓库路径、导出目录解析、CLI 调用参数、插件启用动作规划。
- 支持导出内容直接写入 Obsidian 仓库，而不是只能先落在普通输出目录。
- 支持配置仓库子目录，方便导出内容进入指定分类路径。
- 支持自动规划 Obsidian Bases 相关设置，且预留 `bases+community` 模式。
- 导出报告中开始纳入 Obsidian 配置摘要。
- `src/export-state.js` 现在会记录 `outputPath` 和 `outputKind`，说明导出物已经不再局限于单一 Markdown 文件，开始覆盖 Base 文件等其他落地形态。

从版本视角看，这一批改动让项目更像“语雀内容迁移到 Obsidian 的专用工具”，而不只是“导出 Markdown”。

主要改动文件：

### 5. 加密块处理继续增强

主要改动文件：

- `src/meld-encrypt.js`
- `src/exporter.js`
- `desktop/ui/app.js`
- `src/failure-log.js`

当前未提交版本在加密块上的升级比较完整：

- 新增 `src/meld-encrypt.js`，支持把已解锁内容重新加密为 Meld Encrypt 兼容格式。
- 支持三种导出后策略：不重加密、使用全局密码重加密、按匹配到的原密码重加密。
- 当未提供全局密码、或无法为某些内容块命中密码时，会回退为明文导出，并同时在失败日志 / 警告中记录原因。
- 导出器开始对“已检测到加密块、部分未解锁、已回退明文、重加密失败”等情况形成更完整的总结信息。

这部分能力的价值在于：既照顾迁移可用性，也开始兼顾导出后的私密内容管理。

### 6. 登录、Cookie 与网络访问稳定性增强

主要改动文件：

- `src/yuque.js`
- `src/login.js`
- `src/cli.js`
- `desktop_app.py`

当前未提交改动把登录和会话链路补强了不少：

- 增加 `ensureAuthenticatedCookieFile`，扫描、导出、查询用户前先校验 Cookie 是否可用。
- 增加系统浏览器自动探测逻辑，优先寻找本机 Chrome / Edge。
- 支持登录 profile 目录复用，提升“复用已登录浏览器会话”的成功率。
- 登录流程会优先尝试复用浏览器现有语雀会话，减少重复扫码/重复登录。
- 对 Cookie 持久化后再读取用户信息做了更严格验证。
- `fetchMarkdown` 对“语雀返回 HTML 页面而不是 Markdown”的情况有了更明确报错。
- 拉取 Markdown 时启用了 `linebreak=true`，说明导出结果的文本换行保真度也在继续调整。

这部分属于稳定性工程，用户感知可能没有 UI 那么明显，但对批量导出非常关键。

### 7. 资源下载、占位导出与错误恢复增强

主要改动文件：

- `src/exporter.js`
- `src/failure-log.js`
- `src/markdown.js`

这条主线主要解决“导出时不完美，但尽量别丢内容”：

- 资源下载增加更多错误类型识别，例如 HTML 误返回、非图片响应、空内容、远程链接回退等。
- Markdown 导出后开始检测本地资源引用是否失效，并尝试修复丢失的 `_assets` 路径。
- 当某些图片已无法成功本地化时，会回退为保留远程链接，而不是生成断链 Markdown。
- 对复杂块 worker 崩溃、降级、重试成功、快照兜底等状态会形成独立告警。
- 当正文导出失败时，会尽量生成失败占位文档，并保留可用快照，避免整篇文档完全丢失。

从版本成熟度看，这说明当前未提交分支已经进入“优先保证可恢复性与可追踪性”的阶段。
