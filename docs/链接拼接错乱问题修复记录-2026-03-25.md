# 链接拼接错乱问题修复记录

更新时间：2026-03-25

## 问题背景

在语雀导出的 Markdown 数据中，发现部分文档存在“链接拼接错乱”问题。典型症状不是中文乱码，而是 Markdown 结构本身被压扁或串线，导致：

- 后一个条目的标题被吞进前一个链接
- 多个本应独立的链接被拼接成一个超长链接
- 列表分隔符 `·`、`●`、括号备注等被卷进 URL
- 原本的多行清单被压缩到单行，阅读和点击都异常

本次排查中，问题主要集中在：

- `output/AI/01. 行业信息/AI丨模型汇总.md`

## 典型现象

修复前常见片段类似：

```md
·OpenAI ChatGPT:[https://chatgpt.com/·Google](https://chatgpt.com/·Google)
Gemini:[https://gemini.google.com/·Anthropic](https://gemini.google.com/·Anthropic)
```

或：

```md
●阿里通义千问·国内：[https://tongyi.aliyun.com/qianwen/](https://tongyi.aliyun.com/qianwen/)●海外：[https://chat.qwen.ai/](https://chat.qwen.ai/)
```

或更极端的长串：

```md
Poe:[https://poe.com/·Monica:...·OpenRouter:...·you.com:...](...)
```

## 根因分析

本次确认是“结构拼接错误”，不是编码错误。根因分两层：

### 1. 导出接口过度压缩换行

原实现位于：

- `src/yuque.js`

之前调用语雀 Markdown 接口时使用了：

```txt
linebreak=false
```

这会让语雀尽量不保留原有换行。对于“清单 + 短链接 + 分隔符”的内容，多个相邻条目很容易被压扁到同一行，造成串线。

### 2. 后处理仅用正则重写链接，缺少结构修复

原实现位于：

- `src/markdown.js`

之前的逻辑只负责：

- 改写图片链接
- 改写附件链接
- 改写语雀内部文档链接

但它默认输入已经是结构正常的 Markdown。对于已经被压扁的异常块，没有做：

- 跨行碎片拼接修复
- 纯文本 `标签:https://...` 链条拆分
- 标题和首个子项混排拆分
- 链接后紧跟 `●` / `·` 的列表项断行

## 本次代码修复

### 1. 保留语雀原始换行

已修改：

- `src/yuque.js`

将导出参数从：

```txt
linebreak=false
```

调整为：

```txt
linebreak=true
```

目的：

- 尽量保留语雀原始列表结构
- 从源头减少条目被压成单行的概率

### 2. 新增 Markdown 结构修复预处理

已修改：

- `src/markdown.js`

新增了 `normalizeYuqueMarkdownStructure()` 预处理步骤，并在 `processMarkdown()` 最前面执行。

当前修复能力包括：

- 修复“前一条链接尾部吞入后一条标签片段”的情况
- 将孤立的 `·Google`、`·Anthropic` 这类残片并回下一条标签
- 将纯文本形式的 `标签:https://...` 扩展成标准 Markdown 链接
- 将“章节标题 + 第一个子项”从同一行拆开
- 将 `](...)●` / `](...)·` 这种挤在一起的列表项断行为多行
- 清理只剩一个 `·` 或 `●` 的空残片行

### 3. 补充回归测试

已修改：

- `test/markdown.test.js`

新增并通过的测试覆盖：

- 跨行标签串线修复
- 同行列表项断行
- 链式错乱链接拆分
- 纯文本标签-URL 扩展
- 标题与首个子项拆分

## 注意事项

1. 今后重新导出时，应优先使用当前修复后的版本，避免再次生成同类串线内容。
2. 对于像 `AI丨模型汇总.md` 这种极端长清单文档，建议在新版程序下重新导出一次，效果会比对旧文件做二次修补更可靠。
3. 当前自动修复策略是“保守优先”，不会为了追求全自动而强行猜测本已严重损坏的结构。
4. 如果后续发现更多同类型极端文档，建议单独建立“重导出优先”的处理路径，而不是继续扩大启发式修复规则。
