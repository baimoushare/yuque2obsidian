# 收藏与协作文档导出：实施方案与小范围关键测试

- 日期：2026-10-02
- 对应当前项目版本：0.8.2
- 状态：P0 接口与普通文档样本验证已完成大部分；P1 来源扫描、单篇导出、Sheet 与结构化思维导图已有实现；仍未完成通用复杂块、端到端桌面验收及最终验收。
- 本文依据：当前项目代码检查，以及用户对范围的最新确认。第三方工具案例仅说明存在技术实现路径，不作为当前账号或当前接口的验证结果。

## 一、范围与硬约束

### 1. 核心目标

在保留现有知识库导出的基础上，新增收藏和协作文档导出。以当前登录账号能够正常打开并阅读的具体文档为候选对象，只导出当前文档正文及用户选择的图片、附件、复杂块资源。

### 2. 不做什么

- 不追查、扫描、展开或补全原知识库；不访问知识库列表或目录来发现额外文档。
- 不因为收藏一篇文档或获得单篇协作权限，就导出同库的其他文档。
- 收藏列表中的知识库入口仅显示为“知识库入口，本阶段不展开”，默认不选中、不调用目录接口。
- 协作列表中的知识库、团队入口同样不展开；本阶段只处理其中直接返回的具体文档项。若实际协作入口没有独立文档列表，应明确报告覆盖缺口，不递归扫描知识库补齐。
- 不导出评论、历史版本、多人编辑操作记录；不抓取外部网页全文。
- 不更改文档、不申请额外权限、不绕过登录、密码、访问或明确导出限制。
- 不以“列表中出现”代替“正文可读取”；不以“能阅读”保证结构化内容或所有附件都能取得。

正常可读是候选门槛，不是绕过权限的依据。Markdown 下载失败时，应区分网络错误、接口不可用、正文格式问题与明确的权限/导出限制；对明确限制停止该路径并记录原因，不自动绕过。可在具有相应授权、没有明确限制的情况下，另行评估只读正文转换作为后续能力。

### 3. 对前一版方案的修订

取消“收藏整个知识库的批量展开”和“协作知识库递归导出”。来源知识库名称若列表或当前文档详情已提供，可以作为元数据保留；缺失时标记未知，不为补齐名称访问原知识库。book_id 若由文档项/详情直接提供，可用于本篇文档详情请求，但不得据此请求 catalog_nodes、book_stacks 或同库 docs 列表。

## 三、推荐产品布局与输出组织

### 1. 界面

沿用统一登录、配置、任务进度和日志区。在内容选择区使用两个页签：知识库 / 收藏与协作。实测协作项与收藏项共用 marks 接口，因此在同一来源列表用来源徽标区分，不伪造独立协作入口。

- 知识库页签保持原目录树和原功能。
- 收藏、协作采用可勾选的文档列表，不显示虚构的原库目录树。
- 每项展示标题、作者/团队（已知时）、来源、最近正文更新时间（已知时）、访问状态。
- 支持标题搜索和状态筛选；首次扫描不默认全选。
- 多来源选中同一文档时，显示“选中入口 N 个，去重后文档 M 篇”。
- “未验证”“正文可读”“资源部分失败”“受限”“失效”分开呈现；扫描错误不能冒充空列表。
- 知识库/团队/外部链接入口显示为非文档项，默认禁用或仅保留链接，不自动展开。

### 2. 输出目录

采用文档级归档，不要求补齐原知识库信息。下列为规划结构，不代表已实现：

```text
导出根目录/
├─ 文档/
│  ├─ 已知作者或团队__稳定标识/
│  │  ├─ 文档标题__文档ID.md
│  │  └─ _assets/
│  │     └─ 文档ID/...
│  └─ 来源未知/
│     └─ 文档标题__文档ID或URL摘要.md
├─ 索引/
│  ├─ 收藏.md
│  └─ 协作.md
└─ 报告/
   ├─ 结果.json
   └─ 失败.csv
```

- 同一文档在收藏和协作中仅有一份正文，两个索引都链接到它。
- 如果作者元数据缺失，不额外访问知识库来补齐。
- 通过 manifest 保存 documentKey → 本地路径映射，避免标题变化导致文件增殖。
- 首版保证收藏/协作之间去重；与历史知识库导出副本的跨模式合并另行评估，不声称已解决。
- 原知识库输出结构不变；不自动迁移既有文件。
- 取消收藏或协作关系变化只更新索引，不删除本地备份。
- 来源从多个入口变为一个入口时，正文仍保留；更新关系前必须确认该来源扫描完整，不能用失败/部分扫描误删索引关系。

### 3. 文档元数据

可加入 source_url、document_id、source_types、作者/团队、正文更新时间、导出时间、内容完整性状态。仅写实际取得的字段；收藏时间、协作活动时间不能冒充正文版本。

## 四、最方便的小范围关键测试

原则：先用已登录浏览器确认样本和列表请求，再用源码的最小探针验证单篇。暂不改大界面、不打包新 EXE、不写正式 Obsidian 仓库。

### 步骤 0：准备独立试验目录和白名单

- 关闭其他正在导出的任务；无需退出日常登录浏览器。
- 将所有测试产物写到 runtime-validation 下独立的日期任务目录，与正式输出隔离。
- 首轮选择 3 个有效样本：一篇普通收藏、一篇包含图片的收藏、一篇可以正常阅读的协作文档。
- 若存在同一文档同时被收藏且被邀请协作，将它作为额外的去重样本；附件、只读协作、失效项作为第二轮样本。
- 在本机记录样本 URL、预期标题、来源类型、阅读状态、图片/附件情况。分享时只给脱敏摘要，不需要给出 Cookie 或私有正文。
- 明确允许访问的域名、文档白名单、最大文档数；缺失规范 URL 时只解析该篇文档的重定向，不沿链接爬取其他文档。

### 步骤 1：用现有软件确认账号，再做身份检查

先打开已有软件，确认账号徽标与你当前浏览器账号一致。浏览器登录不等于桌面软件已有可用会话；若软件未登录，只走正常“登录语雀”流程，不点击切换账号，不清理登录资料目录。

以下为当前已存在的命令，可在项目根目录的 PowerShell 执行。只验证登录身份，不扫描知识库、不导出正文；它会发起 /api/mine 请求，旧格式 Cookie 可能由 loadCookies 自动加密升级：

```powershell
node --version
$cookiePath = Join-Path $env:LOCALAPPDATA 'YuqueExporterObsidian\cookies.json'
if (-not (Test-Path -LiteralPath $cookiePath)) {
  throw '未找到桌面软件默认凭据；先在软件中确认登录，或核对实际 cookiePath。'
}
$config = @{ cookiePath = $cookiePath } | ConvertTo-Json -Compress
$env:YUQUE_EXPORTER_CONFIG = $config
try {
  node .\src\cli.js whoami
  if ($LASTEXITCODE -ne 0) { throw '登录验证失败，停止后续测试。' }
} finally {
  Remove-Item Env:YUQUE_EXPORTER_CONFIG -ErrorAction SilentlyContinue
}
```

Node 要求 >=22.12.0。whoami 成功只证明身份有效，不证明收藏/协作正文权限。若软件使用了自定义凭据路径，以实际配置为准。不要读取或粘贴凭据内容，不直接使用项目根目录遗留 Cookie 替代当前软件账号。

### 步骤 2：浏览器 F12 确认列表接口

1. 在已登录语雀浏览器中打开开发者工具 → Network。
2. 选择 Fetch/XHR；进入收藏入口并刷新或翻页，再进入协作入口。
3. 对各入口记录：请求方法、URL path、分页参数、响应里文档项的标识/类型/URL字段、是否分空间。
4. 手工对照白名单样本，确认文档项与文档地址能对应。
5. 如仅返回知识库/团队入口，记录为非文档项，不点击展开来收集库内全部内容。
6. 有第二页时实际翻一页验证分页变化，不仅凭字段名称判断。

只保存去除 Cookie、Authorization、CSRF、分享密码、令牌、签名链接等敏感信息的结构样本。不要导出完整 HAR；不要将“Copy as cURL”原样发出。若工具需要网络采样，也应限制到名单内接口、屏蔽请求头和正文敏感字段。

本步骤确认的是列表发现机制。页面本身可能发起正常内部请求；探针和新导出模块不得主动用知识库目录去扩展范围。

### 步骤 3：实现最小单篇探针，再测试正文

本探针尚不存在，需要在下一轮新增，建议位置 tools/probe-document-sources.js。不要将以下设计误认为当前 CLI 已支持。

探针分为两个独立模式：

- list-only：按已经验证的收藏/协作列表接口取得元数据，默认一页、小上限；不获取正文、不展开知识库。
- document-probe：只处理用户白名单中的 1～3 篇文档，检查详情、Markdown、图片及附件；绝不扫描知识库。

实现要求：

1. 使用 createHttpClient、fetchDocDetail、fetchMarkdown 等现有封装；复用软件保存的 Cookie，不重新导出浏览器凭据。
2. 将完整 URL 校验并转换为 fetchMarkdown 所需的相对路径；若只有 /docs/ID 等短地址，仅解析本篇规范地址。接受的重定向限定到已允许语雀域名，不能将带 Cookie 的客户端用于任意外部链接。
3. book_id 缺失时，验证按文档 ID/规范地址能否取得详情；失败就记录身份解析缺口，不回扫原知识库。
4. 默认顺序请求、每篇之间至少间隔 1 秒；每文档全流程设置可配置超时（建议 180 秒），瞬时网络错误最多重试 1 次；429 遵循 Retry-After，没有该头时停止本轮并报告，401/403 等不盲目重试。
5. 判断 Markdown 是否真实正文，而非登录页、权限页、HTML、空响应；校验预期标题和少量用户选定段落，避免拿错内容。
6. 图片/附件按授权域和当前资源下载安全规则验证：认证仅用于受信任语雀请求，外部 CDN 不携带语雀 Cookie，重定向也不能泄漏凭据。
7. 首先只保存 Markdown 原始结果及脱敏状态；然后在小范围授权试验中验证资源本地化。首版探针若还未接入复杂块，必须标明“仅验证获取链路，不代表最终导出成功”。
8. 任一明确权限或导出限制只记录、不绕过；不进入编辑模式，也不调用修改或自动保存接口。
9. 记录该任务主动调用的接口类别，以证明没有请求 book_stacks/catalog_nodes/同库 docs 列表；凭据值和敏感查询参数不进入日志。

输出建议：sample-results.json、摘要.md、各样本正文以及资源结果。正文和标题属于私有数据，仅留本机；可分享报告使用样本编号、HTTP 状态、错误类别和计数。

### 步骤 4：首轮通过标准与停止条件

| 关键项 | 通过标准 |
|---|---|
| 登录复用 | 当前软件凭据确认是预期账号，没有强制重登/清理资料 |
| 来源发现 | 普通收藏、协作的具体文档能被识别；非文档入口不会展开 |
| 正文 | 三个有效样本都取得对应的真实正文，无登录/错误页伪成功 |
| 单篇边界 | 没有主动查询原知识库列表/目录，也没有导出名单外文档 |
| 只读 | 无远端修改请求，不进入编辑或保存流程 |
| 图片 | 图片样本本地资源可打开、相对引用有效；失败有明确记录 |
| 附件（第二轮） | 文件可打开、类型与大小合理，不是 HTML 错误响应 |
| 去重（第二轮） | 收藏与协作同篇只保存一份正文、保留两个来源关系 |
| 受限/失效（第二轮） | 分别报告不可用/受限，不误报成功，不申请或绕过权限 |
| 安全 | 输出/日志无 Cookie、token、密码等；无凭据传给外部站点 |

登录身份错误、明确权限拒绝、出现限流、页面/响应结构改变或意外扩大文档范围时停止本轮。记录已通过部分与失败原因，不以其他方式偷偷补齐。整个测试不写正式 Obsidian，不全量扫描，不发版。

### 为什么不能直接用当前软件做这轮新功能测试？

原有 `exportBooks` 仍从知识库树规划任务。即便配置 `selectedDocuments`，旧流程也会先读取知识库与目录，既不能保证找到外部单篇，也违背本轮“不深入原知识库”的边界。新来源已另建显式单篇入口与桌面桥接；新界面改动仍须在桌面运行时单独验收。

## 六、风险及待确认事项

1. 收藏与协作的具体接口、类型字段、分页方式、空间隔离仍未知，需要 P0 实测。
2. 本机日常浏览器、现有 EXE 和源码可能使用不同账号/不同凭据路径，先核对 whoami。

4. 只读文档可以获取普通正文，不代表复杂块可按现有编辑辅助路径导出；需要独立能力标记。
5. 同一 ID 可能存在站点/空间作用域问题，documentKey 不宜只用数字 ID。
6. 本地标题与私有正文、图片、附件属于敏感内容；分享结果前必须脱敏，不提交测试产物和登录资料。
