## 1. 执行边界与完成定义

### 1.1 必须遵守的边界

- 只在项目工作区和 runtime-validation/ 隔离目录执行；不得打开、写入或覆盖正式 Obsidian Vault。

- 不执行 git reset --hard、git clean、commit、push、分支创建或依赖树大升级。
- 不把密钥、令牌、正式 Vault 路径中的敏感内容写入日志、测试夹具或文档。

### 1.2 完成定义

只有以下证据全部存在，才可将任务标记为完成：

1. npm test 和 Python 单元测试均通过。
2. 思维导图、简单流程图、复杂流程图、自由画板分别按规则生成目标产物或明确回退产物。
3. 复杂样本结构校验达到 46 节点、49 连线、46 绑定文字、49 起点绑定、49 终点绑定。
4. 隔离 Obsidian 中复杂图能真实渲染；拖动节点时文字和连线跟随；关闭重开后绑定仍存在。
5. 同源幂等、源变化备份、人工修改保护、PNG 清单同步均有测试或运行记录。
6. 项目文档与 Obsidian 副本内容一致，并通过 SHA-256 校验。

## 3. 按模块实施顺序

严格按以下顺序推进，前一步失败时停止后续写入：

1. src/board.js：解析语雀画板 JSON，构建统一 BoardIR，并统计结构完整度。
2. src/board-render.js：依据 BoardIR 分类，生成 Markdown/Markmap、Mermaid、Excalidraw 或 PNG 回退决策。
3. src/excalidraw.js：生成标准 Excalidraw 元素、绑定文字、双端绑定箭头，写入任务目录并回读校验。
4. src/exporter.js：编排导出、增量判断、原子写入、history 备份、文档内插入和 manifest 更新。
5. src/obsidian.js：检测插件和 CLI 能力；插件可用即可生成标准 Excalidraw，不把 CLI 注册作为硬前提。
6. desktop/ui/*、desktop_app.py、src/cli.js：接入图形导出模式、截图模式和状态提示。

每完成一个模块，立即运行最窄的相关测试，并记录命令、结果和输出文件。

## 4. BoardIR 与分类执行规则

### 4.1 BoardIR 最小字段

- 节点：id、文字、形状、坐标、宽高、颜色、层级、原始顺序、思维导图父子关系。
- 连线：id、起点节点、终点节点、起止锚点、线形、箭头标记、颜色、原始点位、有效性。
- 图形级信息：来源类型、结构完整度、布局完整度、不支持元素、告警、推荐输出格式。

### 4.2 分类顺序

先判断结构完整性，再判断布局敏感性，最后选择产物：

- 纯思维导图：树结构完整、无不支持元素 → Markmap；Markmap 不可用 → 普通 Markdown 层级列表。
- 简单流程图：不超过 20 节点、连线有效、无图片/分组/自由绘制、汇入汇出不复杂 → Mermaid。
- 复杂或布局敏感流程图：超过 20 节点、多列、直角线多、复杂汇入汇出或坐标明显影响阅读 → Excalidraw；不可用 → PNG。
- 自由或不完整画板：结构完整度低于 70%，或主要由图片、分组、自由绘制组成 → PNG + 原始 JSON + manifest + 告警。

不要在桌面端暴露内部阈值；如需调整阈值，先增加真实样本回归记录。

## 5. 各类图形的导出步骤

### 5.1 思维导图 → Markmap / Markdown

1. 从 BoardIR 根节点开始，按父子关系生成稳定的层级序列。
2. 对标题、列表符号和换行进行 Markdown 转义，避免节点文本破坏层级。
3. 生成 Markmap 兼容 Markdown；同时保留普通 Markdown 可读内容。
4. 在 manifest 中记录 recommendedFormat=markmap 和插件缺失时的回退原因。
5. 使用目标 Obsidian 的 Markmap 插件实际打开检查：根节点、至少两层子节点和中文文本均可见。

### 5.2 简单流程图 → Mermaid / PNG 回退

1. 将节点 id 映射为 Mermaid 安全 id，显示文本单独转义。
2. 根据主方向生成 flowchart TD 或 flowchart LR。
3. 生成后做语法级检查；若 Mermaid 语法失败、存在不支持元素或布局信息不可表达，转 PNG。
4. 默认 fallback-only 策略下，结构化成功的 Mermaid 不额外截图。
5. 若发生回退，PNG 写入 _assets/boards/<文档>/，并在正文插入稳定图片引用。

### 5.3 复杂流程图 → Excalidraw / PNG 回退

1. 创建批处理任务目录 _assets/boards/<文档>/_excalidraw-jobs/。
2. 按原始坐标生成矩形、菱形、圆角矩形等节点元素，保留尺寸、颜色和层级。
3. 每个节点生成一个原生绑定文字元素：文字的 containerId 指向节点。
4. 每条连线生成带起点、终点绑定的箭头：startBinding.elementId 和 endBinding.elementId 必须指向真实节点；同一节点、同一连接方向的连线统一到该方向边中心。
5. 主轴使用直线；跨列分支使用直角连接；同方向的一对多和多对一不得在节点边缘按比例分散。混合方向时分别使用上/下/左/右边中心，必要的分流只发生在线段离开节点后的外部路径。
6. 写入标准 .excalidraw.md 主文件，随后立即回读 JSON 做结构校验；有原始 points/path 时必须保留中间折点并完成坐标转换，无原始路径时只生成端点直线，不得重新按几何中点取折线。
7. 插件不可用、文件写入失败或结构校验失败时，不中断全书导出，改生成 PNG，并在 manifest 记录告警。

### 5.4 自由画板 → PNG + JSON + manifest

1. 保留原始脱敏 JSON，禁止只输出截图而丢失源数据。
2. 生成可稳定阅读的 PNG，写入 _assets/boards/<文档>/。
3. manifest 至少记录源哈希、生成时间、分类、推荐格式、生成文件、告警和截图状态。
4. 正文只保留一个主入口，避免同时出现多个同名图形文件。

## 6. 增量导出与人工修改保护

每次写入前按以下顺序判断：

1. 读取现有 manifest，比较源 JSON 哈希。
2. 同源且生成文件未被修改 → 跳过重写，记录幂等命中。
3. 源发生变化且生成文件未被人工修改 → 先复制旧文件到 history/，再原子替换。
4. 检测到人工修改 → 不覆盖原文件，生成 *.yuque-update.excalidraw.md 供人工比较。
5. 采用临时文件写入、回读校验、最后替换的原子流程；失败时保留旧文件。
6. 首版不自动清理历史文件、旧 PNG、旧 JSON 或旧 Excalidraw。

重点检查：文件时间变化不能单独作为人工修改依据，必须结合生成哈希或明确的来源标记判断。

## 7. 结构验收步骤

对复杂样本 验收-复杂流程图.excalidraw.md 执行：

1. 读取文件中的 Excalidraw JSON。
2. 统计节点元素、绑定文字、箭头和箭头双端绑定数量。
3. 检查元素 ID 唯一、文字 containerId 有效、箭头两端 elementId 有效，并按“节点 + 起点/终点 + 连接方向”分组检查同方向连接点是否完全相同。
4. 验收目标必须为：

```text
节点 46 / 46
连线 49 / 49
绑定文字 46 / 46
起点绑定 49 / 49
终点绑定 49 / 49
结构错误 0
```

5. 将统计值、锚点分组统计和错误列表写入验证记录，不用看起来正常替代数字证据。

```powershell
Copy-Item 'docs\语雀画板图形导出升级验证记录.md' (Join-Path $obsidianDocs '语雀画板图形导出升级验证记录.md') -Force
Copy-Item 'docs\语雀画板图形导出升级操作层面步骤.md' (Join-Path $obsidianDocs '语雀画板图形导出升级操作层面步骤.md') -Force
```

同步后逐文件比较 SHA-256：

```powershell
$names = @('语雀画板图形导出升级实施方案.md', '语雀画板图形导出升级验证记录.md', '语雀画板图形导出升级操作层面步骤.md')
$names | ForEach-Object {
  $src = Join-Path 'docs' $_
  $dst = Join-Path $obsidianDocs $_
  [PSCustomObject]@{ File = $_; Project = (Get-FileHash $src -Algorithm SHA256).Hash; Obsidian = (Get-FileHash $dst -Algorithm SHA256).Hash }
}
```

三个文件的哈希必须完全一致；不一致时停止交付，重新复制并再次校验。

## 12. 失败处理与回滚

- 分类失败：保留原始 JSON，生成 PNG + manifest，并记录告警。
- Mermaid 失败：不删除 Markdown，改插入 PNG，并记录语法或不支持元素原因。
- Excalidraw 生成或回读失败：保留旧文件，输出 PNG；检查任务目录和错误列表。
- 检测到人工修改：不覆盖原文件，生成 *.yuque-update.excalidraw.md。
- 原子替换失败：删除本次临时文件即可，旧文件和 history 保持不变。
- 隔离 Obsidian 验收失败：停止正式导出，保留截图、日志和隔离 Vault 供复盘。
- 测试失败：先定位根因，不修改无关模块，不以截图或手工观察替代自动化验证。
