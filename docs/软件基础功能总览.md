# 语雀导出桌面版基础功能总览

## 1. 项目定位

本项目的核心目标，是将语雀知识库内容稳定导出为本地 Markdown 资料，并尽可能兼容导入到 Obsidian 使用。  
当前版本已经从早期的命令行脚本，重构为：

- Python `pywebview` 桌面端外壳
- Node.js 导出内核
- 面向 Obsidian 的资源路径与目录结构适配
- 导出失败可追踪、可留档的日志体系

本工具适合以下使用场景：

- 将个人语雀知识库迁移到本地笔记系统
- 批量导出多个知识库并保留原有目录结构
- 下载图片、附件等资源到本地统一管理
- 生成适合 Obsidian 导入的 Markdown 与附件路径
- 在导出失败时保留详细记录，方便后续补导或排查

---

## 2. 当前整体架构

当前软件采用“桌面壳 + 导出内核”的双层架构。

### 2.1 桌面层

桌面层基于 Python `pywebview` 实现，主要负责：

- 启动本地桌面窗口
- 通过内置静态服务加载前端页面
- 暴露给前端的 Python API
- 调起 Node 导出命令
- 汇总导出进度、日志、结果状态

对应核心文件：

- `desktop_app.py`

### 2.2 前端界面层

前端层基于本地静态页面实现，主要负责：

- 展示软件主界面
- 读取和保存配置
- 发起登录、扫描知识库、开始导出
- 显示知识库树形结构
- 展示任务日志、进度、状态信息

对应核心文件：

- `desktop/ui/index.html`
- `desktop/ui/styles.css`
- `desktop/ui/app.js`

### 2.3 导出内核层

导出内核基于 Node.js 实现，主要负责：

- 登录态读取和复用
- 扫描语雀知识库与目录结构
- 拉取 Markdown 内容
- 下载图片、附件和复杂块快照
- 重写 Markdown 链接
- 写入导出文件
- 生成失败 CSV 和导出报告

对应核心文件：

- `src/cli.js`
- `src/exporter.js`
- `src/markdown.js`
- `src/failure-log.js`
- `src/login.js`
- `src/toc.js`
- `src/yuque.js`
- `src/utils.js`

## 3. 桌面端基础功能

### 3.1 本地桌面启动

软件支持通过 `pywebview` 启动本地桌面窗口，而不是单纯依赖浏览器页面。  
桌面窗口启动时会：

- 启动本地静态 HTTP 服务
- 加载 `desktop/ui/index.html`
- 创建桌面窗口
- 将 Python API 挂接给前端调用

### 3.2 配置管理

桌面端支持读取和保存基础配置，默认配置存储在：

- `desktop.settings.json`

当前保存的核心配置包括：

- 浏览器路径 `browserPath`
- Cookie 文件路径 `cookiePath`
- 导出目录 `outputDir`
- 是否下载图片 `downloadImages`
- 是否下载附件 `downloadAttachments`
- 复杂块处理模式 `complexBlockMode`
- 资源目录布局模式 `assetLayout`

### 3.3 前端可调用的桌面 API

目前桌面端已暴露以下核心接口给前端：

- `loadSettings`
- `saveSettings`
- `chooseOutputDir`
- `startLogin`
- `scanBooks`
- `startExport`
- `getJobStatus`
- `cancelExport`
- `openOutputDir`

这些接口已形成桌面端与导出内核之间的标准调用面，后续扩展新功能时，可以优先沿用这一层接口设计。

## 4. 前端界面基础功能

### 4.1 主界面结构

当前主界面主要分为三大区域：

- 功能配置区
- 知识库选择区
- 任务日志区

界面风格已按桌面应用方向进行了统一设计，包含以下视觉特征：

- 圆角玻璃风卡片
- 半透明层叠效果
- 柔和阴影
- 渐变背景与光晕
- 淡紫系主强调色

### 4.2 知识库树形选择

当前前端已支持将扫描出的知识库与目录树，以可折叠目录结构显示出来，功能包括：

- 显示全部知识库
- 显示知识库下全部文档树
- 支持无限层级嵌套
- 支持单独展开和折叠任意层级
- 支持一键展开全部
- 支持一键折叠全部
- 显示知识库总数
- 显示文档总数

这一结构已经从早期“单个知识库滚动预览”改造成更接近语雀原生目录体验的树形目录模式。

### 4.3 导出任务日志与进度显示

前端现已支持实时展示导出过程中的：

- 当前任务状态
- 分阶段日志
- 进度信息
- 错误信息
- 最终结果信息

日志来源于后端 CLI 输出的事件流，前端定时轮询 `getJobStatus` 获取更新。

## 5. 登录与语雀访问能力

### 5.1 登录方式

当前系统主要支持以下登录链路：

- 读取本地 Cookie 文件直接复用登录态
- 必要时启动登录流程，等待用户完成登录

### 5.2 登录态用途

登录态主要用于：

- 扫描用户可访问的知识库
- 拉取知识库目录结构
- 拉取单篇文档 Markdown
- 下载图片、附件及其他资源
- 打开页面以辅助捕获复杂块内容

### 5.3 浏览器依赖

当前导出链路依赖 Chromium 内核浏览器环境，主要用于：

- 页面登录态复用
- 必要页面访问
- 表格和复杂块内容捕获
- 局部截图

## 6. 知识库扫描能力

### 6.1 扫描范围

系统支持扫描用户当前账号下可访问的语雀知识库，并提取：

- 知识库基础信息
- 知识库名称
- 知识库唯一标识
- 目录节点结构
- 文档层级关系

### 6.2 树结构序列化

扫描出的知识库目录会被统一序列化为前端可直接渲染的树状数据结构，便于：

- 前端目录树展示
- 导出计划构建
- 后续做文档级选择
- 后续扩展筛选、搜索、局部导出等功能

---

## 7. Markdown 导出能力

### 7.1 单文档导出

当前导出器会逐篇处理文档，主要流程包括：

- 获取文档 Markdown 内容
- 计算目标文件路径
- 下载文档关联资源
- 重写 Markdown 内部链接
- 写入本地 `.md` 文件

### 7.2 批量导出

当前支持批量导出多个知识库，并保留原有知识库层级结构。  
导出时会按知识库构建完整计划，然后逐篇执行，避免早期简单脚本中“只管一篇篇下载、难以全局追踪”的问题。

### 7.3 文档导出阶段

目前单篇文档导出已拆分为多个阶段，便于日志展示和问题定位：

- 拉取 Markdown
- 改写链接并下载资源
- 捕获表格与复杂块
- 写入 Markdown 文件

前端日志区能直接看到这些阶段性信息。

---

## 8. 资源下载能力

### 8.1 图片下载

当前支持识别并下载文档中的图片资源到本地。  
下载后的图片会统一放入知识库级资源目录中，避免散落到各文档目录里。

### 8.2 附件下载

当前支持识别并下载文档中的附件资源，包括但不限于：

- 常见二进制文件
- 压缩包
- 资料附件
- 文档引用文件

### 8.3 统一资源目录

当前资源目录结构按知识库组织，核心目录包括：

- `_assets/images`
- `_assets/files`
- `_assets/blocks`

其中：

- 图片放入 `_assets/images`
- 附件放入 `_assets/files`
- 复杂块快照放入 `_assets/blocks`

这种目录布局是为 Obsidian 导入兼容性与后期维护而专门设计的。

---

## 9. Markdown 链接重写能力

### 9.1 图片链接重写

当图片下载到本地后，Markdown 中原始的远程图片链接会被替换为本地相对路径链接。

### 9.2 附件链接重写

当附件下载到本地后，文档中的附件链接也会被替换为本地相对路径。

### 9.3 内部文档链接重写

系统支持将语雀内部文档链接，改写为本地导出 Markdown 文件的相对路径。  
这一能力对 Obsidian 导入后保持笔记之间的互链关系非常关键。

### 9.4 路径兼容原则

当前路径重写遵循以下原则：

- 尽量使用相对路径
- 统一使用正斜杠
- 不依赖绝对路径
- 兼容知识库目录层级变化
- 优先保证 Obsidian 能正常识别与打开

---

## 10. 表格与复杂内容处理能力

### 10.1 普通表格处理

对于能够从页面或内容中提取的普通表格，系统会尽量转换为标准 Markdown 表格形式，提升 Markdown 可读性和后续编辑性。

### 10.2 复杂块处理

对于语雀中不适合直接转换为纯 Markdown 的复杂块，当前采用“快照优先”的处理策略。  
这类内容包括但不限于：

- 数据表
- 思维导图
- 画板
- 其他页面型嵌入块

### 10.3 复杂块导出方式

当前复杂块的处理方式主要是：

- 尝试从页面中识别复杂块
- 截图或生成本地快照资源
- 将快照保存到 `_assets/blocks`
- 在 Markdown 中插入相应引用或补充说明

### 10.4 降级策略

如果某篇文档无法完整以 Markdown 形式导出，系统不会直接中断整个任务，而是会：

- 记录失败日志
- 尽量生成占位 Markdown
- 保留错误信息和资源说明

这样可以最大程度减少整批任务因个别文档失败而中断。

---

## 11. Obsidian 兼容能力

### 11.1 目录结构兼容

导出结果会尽量保留知识库原始目录层级，使导入到 Obsidian 后仍具备清晰的知识结构。

### 11.2 资源路径兼容

所有资源链接都会尽量改写为 Markdown 能直接识别的相对路径形式，减少导入后资源丢失的风险。

### 11.3 内部笔记互链兼容

通过重写语雀内部链接，本地 Markdown 文件之间可以继续互相跳转，降低迁移后的断链问题。

### 11.4 资产集中管理

知识库级 `_assets` 目录使图片、附件、复杂块快照形成可统一备份、统一迁移、统一清理的结构，适合长期维护。

---

## 12. 导出失败记录与日志体系

### 12.1 实时日志

当前导出过程中，系统会持续输出阶段性日志，用于展示：

- 当前正在处理的知识库
- 当前正在处理的文档
- 当前所在处理阶段
- 进度信息
- 警告或错误信息

### 12.2 失败 CSV 记录

当前系统已实现失败日志自动落盘，格式为 CSV，便于：

- 直接用 Excel 打开
- 后续复盘问题
- 批量定位失败文档
- 做补导任务清单

失败日志核心字段包括：

- `timestamp`
- `book_name`
- `doc_name`
- `yuque_path`
- `target_md_path`
- `phase`
- `error_type`
- `error_message`
- `retry_count`

### 12.3 失败日志文件

每次导出任务会生成：

- 一份带时间戳的失败日志 CSV
- 一份最新失败日志副本 `export-failures-latest.csv`

### 12.4 编码兼容

失败 CSV 使用 `UTF-8 with BOM` 输出，默认兼容 Windows 下 Excel 直接打开中文内容。

---

## 13. 导出结果与报告文件

除 Markdown 和资源文件外，当前还会输出辅助报告，用于追踪本次导出结果。

当前主要包括：

- 导出清单 `export-manifest-*.json`
- 导出报告 `export-report.json`
- 导出失败日志 `export-failures-*.csv`
- 最新失败日志 `export-failures-latest.csv`

这些文件可用于：

- 核对哪些文档已经导出
- 复盘失败项
- 辅助二次导出
- 辅助后续做增量导出、恢复、重试功能

---

## 14. 当前主要操作流程

软件当前的基础使用流程如下：

1. 启动桌面程序
2. 加载本地配置
3. 选择导出目录
4. 登录语雀或复用已有 Cookie
5. 扫描知识库
6. 在前端界面中选择要导出的知识库
7. 启动导出任务
8. 在日志区查看实时处理进度
9. 导出完成后检查输出目录、报告文件和失败 CSV
10. 将导出目录导入到 Obsidian 中使用

## 17. 当前已知限制

虽然当前版本已具备可用的桌面导出能力，但仍有一些现实限制需要长期记录：

- 语雀复杂块无法全部无损还原为可编辑 Markdown
- 数据表、思维导图、画板等复杂内容目前以快照保真优先
- 部分语雀页面行为如果后续调整，可能需要同步更新抓取逻辑
- 浏览器环境与登录态仍是导出链路的重要前提
- 当前更偏向“本机稳定使用”，尚未以完整安装版发布为主要目标

## 19. 结论

截至当前版本，本项目已经从一个偏脚本化的语雀导出工具，升级为一个具备桌面界面、知识库树选择、资源下载、路径重写、失败留档、Obsidian 兼容导出的完整桌面应用雏形。

它当前最核心的价值已经比较明确：

- 可以在本地可视化操作
- 可以批量导出语雀知识库为 Markdown
- 可以下载图片、附件和复杂块快照
- 可以为 Obsidian 提供更稳定的目录和路径兼容
- 可以在失败时保留 CSV 留档，便于长期迁移和维护

这份文档可作为当前阶段的项目基础功能档案，后续每次新增核心能力时，建议继续在 `docs` 目录下同步维护更新。
