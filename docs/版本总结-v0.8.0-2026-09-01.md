# v0.8.0 版本总结：OTA 自动更新与知识库扫描增强

- 版本：v0.8.0
- 日期：2026-09-01
- 发布主题：OTA 自动更新与知识库扫描增强
- 交付状态：本地功能、自动化测试和 EXE 构建已完成；宝塔 HTTPS 实机下载/安装等待上传首个更新包后验收。

## 一、为什么做

本次围绕两个使用问题收敛交付：

- 用户需要桌面程序能够从自有宝塔站点 `update.baimoushare.cn` 安全接收 Windows 更新，避免每次手工替换 EXE。
- 程序右下角已有咖啡入口，需要紧邻增加设置入口；当前设置范围只放“自动更新”，不扩展成通用设置中心。
- 自动扫描不能因一个已删除、迁移或无权限的知识库失败而中断全部知识库加载。

## 二、功能边界与架构

```text
应用设置 → HTTPS stable/manifest.json + manifest.sig
         → Ed25519 验签 → 下载 EXE → SHA-256/可选 Authenticode 校验
         → 旧 EXE 复制出的 helper 替换文件 → 新版启动健康标记
         → 成功保留新版本；超时或异常恢复 .previous
```

- 更新源是静态文件站点：`https://update.baimoushare.cn/yuque2obsidian`。
- 客户端只接受 HTTPS、同域且位于指定目录下的更新包；拒绝 HTTP、重定向、站外地址和含凭据 URL。
- `v0.8.0` 是首个具备 OTA 能力的版本，仍须手工安装一次；从 `v0.8.1` 开始可在应用内升级。
- 自动检查仅提示，不自动下载或安装；下载、安装都由用户主动确认，登录/扫描/导出任务运行时禁止安装。
- 仅支持 Windows x64 单文件 EXE 的 stable 更新；开发模式只能检查更新，不能覆盖源码运行入口。

## 三、本次重要变化

### 新增功能

- 在右下角咖啡图标右侧新增齿轮设置入口。
- 新增自动更新弹窗：启动后自动检查开关、当前版本、上次检查、检查、下载、取消和安装重启状态。
- 新增 Ed25519 detached manifest 签名、SHA-256 下载与安装前二次校验、下载进度和可取消下载。
- 新增独立更新助手：主程序退出后替换 EXE，保留 `.previous`，新版未完成健康检查时自动回滚。
- 新增 `publish_ota.ps1` 与 `tools/ota_publish.py`，生成可上传至宝塔的 `stable/` 与不可变 `releases/v版本号/` 目录。

### 已有功能调整

- EXE 包现在携带 `package.json`，桌面端从统一版本源读取当前版本。
- 自动扫描改为隔离单个异常知识库并重试临时网络错误，保留可访问知识库的扫描结果。

### 问题修复

- 更新助手不再接受任意任务路径或任意 EXE；任务、安装包、健康标记必须位于受信任的用户更新目录，并与已验证下载记录一致。
- 健康标记先核对新 EXE 的内置版本，防止旧二进制被错误发布为新版本后误判升级成功。
- 单实例锁在创建前清空 Win32 上次错误码，避免历史 `ERROR_ALREADY_EXISTS (183)` 误判。
- OTA 发布脚本使用 UTF-8 BOM，确保 Windows PowerShell 5 能正确解析中文脚本内容。
- 同步扫描诊断日志使用微秒时间和随机后缀，避免连续失败互相覆盖。

### 文档与部署

- 新增 [OTA 自动更新实施与发布说明](./OTA自动更新实施与发布说明.md)，包含密钥保管、宝塔目录、Nginx 缓存、上传顺序、回滚和验收步骤。
- 更新清单与签名文件应最后上传到 `C:/wwwroot/update.baimoushare.cn/yuque2obsidian/stable/`；版本 EXE 上传到不可变 `releases/v版本号/`。
- 私钥仅存本机 `%LOCALAPPDATA%\YuqueExporterObsidian\ota-signing\ed25519-private.pem`，不进入 Git 或服务器。

## 六、发布操作（v0.8.1 起）

```powershell
$key = Join-Path $env:LOCALAPPDATA 'YuqueExporterObsidian\ota-signing\ed25519-private.pem'
.\publish_ota.ps1 `
  -Version 0.8.1 `
  -Title '简短更新标题' `
  -Note '第一条重要变化' `
  -PrivateKeyPath $key
```

按 `release/ota-upload/上传顺序.txt` 上传。先上传 `releases/v0.8.1/`，最后替换 `stable/manifest.json` 与 `stable/manifest.sig`；上传后再用已安装的 v0.8.0 进行真实检查和下载。
